- **Commands run:** about 45 cutroom invocations across 11 shell calls, in this order: `cutroom guide`; `cutroom guide workflow|edit|overlays|render|verify|pitfalls|perceive` (7 separate topic calls, in one shell line); `cutroom doctor`; `cutroom init talk.mp4`; `cutroom inspect`; `cutroom transcribe`; `cutroom transcript`; `cutroom transcript --suspects`; `cutroom transcript --words --from 1 --to 8`; `cutroom edit tighten`; `cutroom timeline`; `cutroom timeline --joins`; `cutroom edit cut --from "The first thing you need" --near 6.31 --to "first thing." --dry-run`; the same without `--dry-run`; `cutroom edit cut --from "By the way" --to "keyboard." --dry-run`; the same without `--dry-run`; `cutroom timeline`; `cutroom timeline --joins`; `cutroom transcript --suspects`; `cutroom overlay add text ... --layout title --at "Hi," --to "server."`; `cutroom overlay add text ... --layout lower-third --at "Then install" --to "on it."`; `cutroom overlay list`; `cutroom look --output 1.5`; `cutroom look --output 7.5`; `cutroom overlay rm o2`; `cutroom overlay add ... --duration 2.2`; `cutroom render --preview --range 0:00-0:10`; `cutroom look --output 1.9`; `cutroom look --output 7.2`; `cutroom render --dry-run`; `cutroom render`; `cutroom check`; `cutroom transcript --file out/final.mp4`; `cutroom look --cuts`. - **Errors hit:** none. No command failed. The only warning was `WARN[retake-kept]` after tighten, which printed a ready-made `edit cut` with `--near 6.31`. That fix line worked as printed.

- **Guessed wrong:** I assumed `--to` on `overlay add` would end the card on a phrase and that the lower-third default duration (4 s) would fit. It did run into the next line's speech. The first lower-third was only 1.43 s because `--to "on it."` ends early, so I removed it and re-added it with `--duration 2.2`. I also expected the `--near` value in the retake fix to be a source time, which it is, but that is only stated in the parenthetical after the command.

- **Confusing output:** `cutroom timeline` prints output times on the left and source ranges on the right, and the `s1`, `s3`, ... segment ids skip numbers after cuts (`s2`, `s5` vanish). That is fine, but it is easy to misread. `overlay list` reports overlay windows in output time while `overlay add` reports anchor words in source time (`talk 0:14.020`). The `look` labels show both (`out 0:01.900 = talk 2.37`), which helped, but I had to check which time was which. The `transcript` output is one dense line per phrase, which is fine for 7 phrases.

- **Missing:** an `overlay edit` or `overlay set --duration` command. Changing a duration meant `overlay rm` and then `overlay add`, which mints a new id (o2 became o3). I also wanted a way to listen to the joins with the render rather than only through `look --cuts`. A `check --joins` or `listen` summary across all cuts would have helped, since I could not listen to every join.

- **Not sure it's right:** I did not listen to the audio at the three joins that remain (the 0.30 s pauses after the intro, after "old laptop", and after "on it."). `check` reports sync and words in order, and `transcript --file out/final.mp4` reads the render as one clean line, so I trust the join audio, but I did not hear it. The lower-third timing (6.5 to 8.7 s) matches the "Then install Linux" speech at about 6.4 to 8.1 s in the output, but I judged that from the transcript timing, not by watching a speaker. Overlay text was checked visually from two `look` frames (`out 0:01.900`, `out 0:07.200`), and `check` confirmed both cards are visible on the render and gone on the frames just outside their windows.

- **Best part:** the anchor-by-words model made overlays easy to place: `--at "Hi," --to "server."` and `--at "Then install" --to "on it."` needed no timestamp arithmetic. The retake warning gave a ready command, and `--dry-run` previewed the join before applying it.
