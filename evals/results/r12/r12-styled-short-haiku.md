# Friction report: r12-styled-short-haiku

- **Outcome:** done. `out/short.mp4` (720x1280, 7.267 s) passes `cutroom check` with 0 warnings, and the rendered words read back as the three steps in order, with the cat aside gone.
- **Commands run:** about 35 cutroom invocations, in order: `guide`; `guide shorts`, `guide overlays`, `guide style`; `guide workflow`, `guide edit`, `guide verify`; `doctor`; `init talk.mp4`; `inspect`; `transcribe`; `transcript`; `short --from "The first thing you need is an" --to "update command." --name steps`; `timeline --project shorts/steps`; `transcript --suspects talk`; `edit cut --from "By the way," --to "the keyboard." --project shorts/steps`; `edit frame --size 720x1280 --project shorts/steps`; `timeline --joins`; `style --help`; `overlay add --help`; `captions --help`; `style captions ... --project shorts/steps`; `style cards ... --project shorts/steps`; `overlay add text "3 steps to a home server" --at "The first thing you need" --duration 4 --layout top`; `overlay list`; `captions --burn`; `look --output 2.07`, `5.5`, `0.5`; `render --preview --range 0:00-0:05`; `render out/short.mp4`; `check out/short.mp4`; `timeline`; `transcript --file out/short.mp4`.
- **Errors hit:** none from cutroom. No `error[...]` lines and no non-zero exits.
- **Guessed wrong:** `short` built a 1080x1920 project and warned that the 1280x720 source is enlarged 2.7x. The guide already says to use `--size 720x1280` for a 720p source, and I did not run `short --help` to see whether `short` takes a size flag, so I fixed it afterwards with `edit frame --size 720x1280`. The `timeline` output also said "1080x1920" right before I changed it, so the two numbers were confusing for a moment.
- **Confusing output:** `captions --burn` prints "lower thirds move up above them" with no lower thirds in the edit, which I could not tell was harmless. `look` on this talk shows solid colour bars, not a person, so the framing guidance (`--anchor`) could not be judged.
- **Missing:** a way to see the source content in `look` (this file is a colour-bar test pattern, which I only noticed from the frames). Also a single flag or preset for "9:16 short with channel look" would have saved about ten style and overlay calls. I also could not find how to set `--outline-width` default for captions without guessing.
- **Not sure it's right:**
  - The title card's top position is confirmed inside the vertical safe zone by `check` (`safe-zones` passed, box y 174–993 of 1280-high frame scale), but I did not see it over a real app screen, and the source frames are colour bars, so I cannot judge overlap with real content.
  - The captions' vertical position at y 0.58 and the hot pink colour are confirmed in the `look` frames, which show the pink text with a black outline on bars, but I could not check contrast against a real picture.
  - The word check used the same `base.en` model as the transcript, so it confirms the cut and not the recognition. I did not run a larger model.
  - I chose 720x1280 over 1080x1920 to avoid soft upscaling. YouTube Shorts often prefers 1080x1920, so this is a tradeoff the user may want to change.
- **Best part:** `cutroom short --from ... --to ... --name` made the project in one call, and `timeline`, `timeline --joins` and `check` each told me exactly what to fix next. The `check` output lists every rule it passed, which made the verification easy to read.
- **One change:** have `short` accept `--size` and `--style`-like flags that set the output and channel look in the same call, or add a `--preset shorts-channel` that applies burned-caption and card styles. Repeated `style` calls made the setup long.
