- **Commands run:** about 35 cutroom invocations across 9 shell calls, in order: `cutroom guide`; `cutroom guide workflow|edit|overlays|render|verify|perceive|pitfalls`; `cutroom doctor`; `cutroom init talk.mp4`; `cutroom inspect`; `cutroom transcribe`; `cutroom transcript`; `cutroom transcript --suspects`; `cutroom transcript --words --from 0:06 --to 0:13`; `cutroom edit tighten`; `cutroom timeline`; `cutroom edit cut --from "The first thing you need" --near 6.31 --to "first thing." --dry-run`; same for `--from "By the way" --to "keyboard."`; the two real `edit cut` runs; `cutroom timeline`; `cutroom timeline --joins`; `cutroom overlay add text "Home Server in 3 Steps" --layout title --at "Hi, today" --to "home server."`; `cutroom overlay add text "Step 2: Install Linux" --layout lower-third --at "Then install" --duration 2.5`; `cutroom overlay list`; `cutroom look --output 1.5`; `cutroom look --output 7.0`; `cutroom render --preview --dry-run`; `cutroom render --preview`; `cutroom check out/preview.mp4`; `cutroom render`; `cutroom check out/final.mp4`; `cutroom transcript --file out/final.mp4`; `cutroom overlay list`.
- **Errors hit:** none. No command failed.
- **Guessed wrong:** nothing failed, but I had to reason about `--near`. The retake warning's suggested command uses `--from "The first thing you need" --near 6.31`, and `--near` is a source time, not an output time. The command ran correctly, but the mix of a text anchor and a time in one command is easy to get wrong. The `--layout title` value for the title card was not in the guide's examples; I inferred it from the overlays guide's layout list.
- **Confusing output:** `cutroom timeline` (after tighten) listed a `retake-kept` WARN plus a ready-made fix line. That is useful, but the fix is a multi-word `--from` that only works because `--near` disambiguates it. The `--joins` output shows `s1|s3` segment labels, which I had to map back to the timeline rows by hand. The `look` output labels each frame with a source time (`talk 1.97`), not the output time, so I read two different clocks.
- **Missing:** a way to check the cut joins by listening inside the final render without going through a spectrogram PNG. `cutroom listen --output` exists, but I did not use it, so the joins are unverified by ear. A `--json` view of the overlay positions relative to the anchored words would also have helped me confirm the overlay ends before the speaker's next sentence.

  - Transcripts came from `base.en`, the only model installed. The word check in `check` re-transcribes with the same model, so it confirms the cut, not the recognition. The transcript read "UM" correctly as a retake marker, but I did not check it with a larger model.
  - I chose the title card's span as "Hi, today" through "home server.", which ends at output 3.7 s. I did not confirm that the speaker has finished the sentence at that moment on the final frame.
  - The lower third anchors to "Then install" (output 6.5 s). I did not check that "install Linux" is audible or readable at that point.
  - The `look` frames I viewed are test-pattern colour bars, so I could only check card placement and legibility, not how the card looks over real footage.
- **Best part:** `cutroom guide` plus `transcript --suspects` made the edit decisions obvious. The `--dry-run` on `edit cut` showed the join before I committed, and `check` gave a clear PASS/FAIL table with the overlay visibility frames spelled out.
- **One change:** let `cutroom edit cut` accept a `--from`/`--to` pair in the same units as the warning it came from (or let the retake warning print a `--from`/`--to` pair without `--near`), so the suggested fix is a single unambiguous command without mixing a text anchor and a source time.
